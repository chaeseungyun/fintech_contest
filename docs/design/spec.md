> **상태: 적용 완료 (2026-09-23, 커밋 23dc6e6).** 아래 §4의 "기존" 서술은 적용 전 기준이다.
> 적용하면서 시안과 다르게 둔 것은 맨 아래 §9에 적었다.

이 문서는 **시안의 의도**를 적은 것이다. 구현은 `CLAUDE.md`를 따른다 —
둘이 충돌하면 **CLAUDE.md가 이긴다.** 시안 쪽이 틀린 것이다.

시안 HTML(`docs/design/*.html`)은 브라우저에서 바로 열리는 정적 파일이다.
**앱 코드가 읽지 않는다.** 마크업·px 값을 눈으로 확인하는 용도다.
`docs/archive/design_v2.html`과 같은 성격이고, 그것을 대체한다.

| 파일 | 화면 | 대응하는 라우트/탭 |
|---|---|---|
| `01-home.html` | 홈 (은행 홈) | `tab: home` |
| `02-switch.html` | 바꿔 볼 항목 (바텀시트) | `hub` |

## 적용 순서

한 번에 다 고치지 않는다. 단계마다 `npm test`가 통과해야 다음으로 간다.

1. **토큰만 교체** — `src/styles.css`의 `:root` 블록을 `docs/design/tokens.css`로 갈아끼우고
   Pretendard를 설치한다. 화면 코드는 건드리지 않는다. 이 단계만으로 톤의 절반이 옮겨간다.
2. **화면 하나씩** — `Home → Verdict → Impact → ActionPlan → Timeline → Hub → Analyzing` 순서.
   한 화면을 고치고 확인한 뒤 다음으로 간다.
3. **플로우 변경** — `store.ts`의 스택 구조를 건드리므로 맨 마지막에, 따로 한다. (§6)

### 1단계: 폰트

`styles.css`는 이미 `Pretendard`를 font-family에 적어 두었지만 실제로 로드하지 않는다.
CDN을 쓰지 않는다 — 정적 빌드로 배포하므로 패키지로 넣는다.

```bash
npm i pretendard
```

```ts
// src/main.tsx 최상단
import 'pretendard/dist/web/variable/pretendardvariable.css';
```

약관 원문·날짜에 쓰는 mono는 `IBM Plex Mono`다. 같은 방식으로 `@fontsource/ibm-plex-mono`를
넣거나, 없으면 `ui-monospace` 시스템 폰트로 두어도 된다 — **본문과 구분되기만 하면 된다.**

## 2. 디자인 토큰

전체 값은 `docs/design/tokens.css`. 변수 이름은 기존 것을 그대로 쓴다 — 화면 코드가 안 깨진다.

**바뀐 것 중 의도가 있는 것만 적는다.**

- **액센트가 파랑에서 네이비로**(`--brand: #2f63f5 → #18233C`). 파랑은 "이득"으로도 읽혀서
  손익 색과 섞였다. 네이비는 중립이라 액션에만 쓰이고, 손익은 초록/벽돌이 전담한다.
- **`--up`이 파랑에서 초록으로**(`#2f63f5 → #0b6b52`). 손익 색은 **단 두 개**다:
  `--up`(지켜지는 혜택·절감) `--down`(잃는 혜택). 이 둘 말고 금액에 색을 쓰지 않는다.
- **`--mute`를 `#98a2b3 → #6e737b`로 어둡게.** 흰 배경에서 3.1:1이라 WCAG AA에 못 미쳤다.
  캡션·보조 설명이 전부 이 색이다.
- **`--src-hold`를 `#6b7280 → #5a616b`로.** 같은 이유(태그 배경 위 3.9:1).
  나머지 출처 태그 색은 CLAUDE.md 표 그대로다.
- **`--src-calc`는 더 이상 쓰지 않는다.** CLAUDE.md 규칙이 *태그 없음 = 계산 결과*다.
  변수는 남겨 두되 화면에서 붙이지 않는다.
- **면이 아니라 선으로 나눈다.** 회색 배경(`--bg`)을 흰색으로 올리고, 카드는 그림자 없이
  `1px solid var(--line)`로만 구분한다. 카드 안의 행 구분은 더 옅은 `--line-2`.
- **`--highlight: #f7efd8`** 추가 — 약관 원문에서 추출 구간(`condition.spans`)에 깔리는 색.

### 타이포

| 쓰임 | 값 |
|---|---|
| 화면 제목 (h1) | 22–27px / weight 700 / `letter-spacing: -0.05em` |
| 섹션 제목 (h2) | 14.5–15px / 600 / `-0.03em` |
| 항목 이름 (b) | 13.5–14px / 600 |
| 본문 | 12.5–13px / 400 / `line-height: 1.65` |
| 캡션 | 11–11.5px / 400 / `--mute` |
| 큰 금액 | 38px / 600 / `-0.05em` / `font-variant-numeric: tabular-nums` |
| 항목 금액 | 14px / 600 / tabular-nums |
| 날짜·약관 원문 | `--font-mono` 10–12px |

**한글 제목은 `letter-spacing`을 음수로 조인다.** Pretendard는 기본 자간이 넓어서
그대로 두면 금융앱 제목처럼 보이지 않는다. 금액은 예외 없이 `tabular-nums`다 —
숫자가 바뀔 때 자릿수가 흔들리면 안 된다.

### 컴포넌트 규칙

- 카드: `border: 1px solid var(--line)` · `border-radius: var(--r-xl)` · 그림자 없음
- 아이콘 타일: 34–40px 정사각 · `border-radius: 11–13px` · 배경 `--surface-2`
- 아이콘: **inline stroke SVG만.** `stroke-width: 1.6`, `stroke-linecap: round`. 이모지 금지(이미 CLAUDE.md 규칙)
- 터치 타깃 `min-height: 44px`
- 목록은 `display: flex` + `gap`. 형제 간격을 margin으로 주지 않는다

## 3. 삭제한 것

### 가짜 상태바·홈 인디케이터

`AppShell`의 `.statusbar`("9:41 · 신호 · 배터리")와 `.homebar`를 **뺀다.**
실기기에서는 진짜 상태바가 그 위에 겹쳐 그려져 두 겹으로 보인다.
대신 화면 맨 위 **54px를 빈 채로** 둔다(safe area).

데스크톱 폰 프레임에서도 마찬가지다 — 프레임 안에 상태바를 그리지 않는다.

### 홈의 혜택 합계

홈에 있던 "지금 받고 있는 우대 혜택 연 850,000원"을 뺐다.
**이 기능은 은행 앱 안의 메뉴다**(CLAUDE.md). 홈 상단은 은행이고, 이 기능은 배너와
퀵메뉴 한 칸으로만 들어온다. 혜택 합계는 혜택 탭의 `summarycard`가 맡는다.

홈 배너의 `"상품 n개 · 우대 조건 m건 상시 분석 중"` 라이브 줄은 **남긴다** —
CLAUDE.md가 "상시 분석 중은 홈이 말한다"고 지정한 자리다. 값은 `watch.ts`에서 온다.

## 4. 화면별 변경점

### 01 · 홈 (`Home.tsx`)

순서: 은행 로고 + 샘플 칩 → 총자산 카드 → 퀵메뉴 8칸 → FinStay AI 배너 → 이번 달 점검 카드.

- 샘플 칩을 헤더로 올렸다. `"샘플 데이터 · 기준일 2026.09.08"`, mono, 테두리 pill.
  처음 보는 사람이 설명 없이 데모임을 알아야 한다.
- 총자산이 인사말보다 위다. 은행 홈의 문법이다. 금액은 600 weight 28px.
- 퀵메뉴는 `home.quickMenu` 8개를 4×2 그리드로. `ai` 항목이 분석 진입점이다.
- 배너는 네이비 면. 서비스명(`brand.service`)·태그라인(`brand.serviceTagline`)·라이브 줄 3단.
- 이번 달 점검 행은 **혜택 탭으로** 간다. 해지 분석으로 튀지 않는다(CLAUDE.md).

### 02 · 바꿔 볼 항목 (`Hub.tsx`)

**전체 화면에서 바텀시트로.** 홈이 뒤에 비치고 시트가 70%를 덮는다.

- 홈 배너 → 허브 → 항목 선택(3탭)이 홈 → 시트 → 분석(2탭)이 된다.
- 제목은 `home.bannerTitle`, 본문은 `home.bannerBody` 그대로.
- 행에는 **금액이 없다**(CLAUDE.md). 연결 건수 · 영향 상품 · `trigger.missing`만.
  `missing`은 `--warn` 색 한 줄로 따로 뺀다.
- 첫 행(카드 해지)만 테두리 강조. 나머지는 hairline 구분 목록.

시트로 바꾸면 `AppShell`이 필요 없다 — 탭바도 나오지 않는다.
구현은 `stack`에 `hub`를 그대로 쌓되 `AppShell` 대신 시트 컨테이너를 쓰는 쪽이 간단하다.

### 03 · 분석 중 (`Analyzing.tsx`)

- 진행률을 막대에서 **링**으로. 140px SVG, `stroke-width: 3`, 가운데 퍼센트와 `n / 4 단계`.
- 단계 4개. 첫 단계는 `"추출해 둔 조건 불러오기"` — **약관을 방금 읽은 것처럼 쓰지 않는다**(CLAUDE.md).
- `"시연용 샘플 조건 · 실시간 약관 추출·AI 호출 없음"`을 mono로 제목 바로 아래.
- 문구·숫자는 전부 `derive().steps`에서 온다. 연출용 값을 만들지 않는다.

### 04 · 비교 결과 (`Verdict.tsx`)

결론 → 순손익 → 비교 기준 → 손익 막대 → 차트.

- 헤드라인은 `"확인된 조건에서는"`으로 한정한다. 강조 단어(유지/변경)만 색을 준다.
- 순손익 38px / 600 / tabular-nums. 부호를 반드시 붙인다.
- **`BasisStrip`을 금액 바로 아래에** 둔다 — `무엇 vs 무엇 · 기간 · 기준일 · 가정`.
  `derive().basis`에서만 온다. 이게 빠지면 숫자가 무엇과의 비교인지 알 수 없다.
- 손실/절감 비율 막대: 높이 10px, 두 조각 사이 3px 간격, 아래에 색 점 + 금액 범례.
  **합계를 다시 크게 그리지 않는다** — 근거 줄은 결과 상세의 몫이다.
- 차트 아래 문구는 `horizon.reason`으로 고른다. 구간 숫자만 보고 문장을 짓지 않는다.
- 시점 스트립(`"9월 30일이 지나면 이번 달 우대가 확정"`)에서 타임라인으로 바로 들어간다.
  기존에는 결과 상세 안쪽 ghost 버튼에 묻혀 있었다. **판정일 계산이 이 프로젝트의 차별점이라
  진입을 한 단계 얕게 뒀다.**

#### 유지 기간별 손익 차트 (`HorizonChart`)

- 0선 기준 **발산 막대**. 음수는 `--down`, 양수는 `--up`, 0선은 `--line` 1px.
- 막대 5개(0·3·6·9·12개월), 폭 36px, `rx: 3`.
- **값 라벨은 양 끝에만.** 모든 막대에 숫자를 박지 않는다(CLAUDE.md: 차트에 숫자를 박지 않는다).
- 강조 구간은 막대 위 작은 텍스트로("만기 뒤"). **배지를 "추천"이라 부르지 않는다.**
  `reason === 'positive'`면 "손익분기", `savings`가 없으면 강조 자체를 그리지 않는다.
- x축 라벨은 mono 10px. 강조 구간만 `--ink`, 나머지는 `--mute`.

### 05 · 결과 상세 (`Impact.tsx`)

순서는 CLAUDE.md 그대로: **① 상품 자체 변화 → ② 연결된 상품 영향 → 합계 근거 →
③ 변경 비용(일회성) → 타임라인 → 유지 조건 → 갈아타기 후보 → 체크리스트.**

- 대상 상품 카드와 `BasisStrip`을 맨 위에.
- 펼친 행: 쉬운 말 한 문장 → 필드 목록(확인 주기 / 다음 우대 확인일 / 실적 확인 / 계산 원금 /
  연간 손실) → 약관 원문 → `근거 원문 · 값 수정` 버튼.
- **약관 원문은 mono 12px / line-height 1.8**, `condition.spans` 구간에 `--highlight` 배경.
  아래에 출처 문서명과 `제외 · …`, `추출 신뢰도 nn%`.
  이 블록이 "약관에서 뽑았다"를 눈으로 보여주는 자리다. 크게 쓴다.
- 출처 태그는 **약관 / 보유 상품 정보 / 사용자 확인 세 개만.** 계산 결과에는 붙이지 않는다.
- 합계 근거 줄은 회색 면 한 줄: `절감 30,000 − 손실 194,000` + 순손익.
  **비교 결과의 숫자를 다시 크게 그리지 않는다.**
- 후보 카드마다 `이 안으로 절차 보기`(→ `store.chosen`) + `신청 경로 보기`(`ContactSheet`),
  목록 끝에 `새 상품 없이 {verb}` 행. **"신청하기" 버튼은 없다.**
- 후보 배지는 `이득`. "추천"이라 쓰지 않는다.
- footer: `keep`·`pending`이면 강조 버튼이 "다른 항목도 분석해보기",
  해지 절차는 `"그래도 {verb}한다면 · 절차 보기"` 텍스트 링크로 한 단계 아래.

### 06 · 우대 확인일 · 변경 가능 구간 (`Timeline.tsx`)

- 제목이 결론을 말한다: `"9월 30일이 지나면 이번 달 우대가 확정됩니다"`.
- 축은 SVG. 변경 가능 구간을 `--up` 연한 면으로 깔고, 점은 종류별로 색을 나눈다:
  오늘(네이비 채움) · 판정일(테두리만, `--warn`) · 안전 시점(`--up` 채움) · 만기(`--down` 채움).
- 라벨 겹침은 y를 한 줄 내려서 푼다(09.20처럼). 날짜는 mono.
- 조건별 목록에 `--src-doc` 태그. `회복 불가`는 `--down` 텍스트.
- `되돌릴 수 없는 우대` 카드는 상품 · 우대폭 · 만기 · 결과를 **다 적는다**.
  "우대의 만기" 같은 줄임말을 쓰지 않는다(CLAUDE.md).
- "안전"이라는 말을 기한에 쓰지 않는다 — 화면 문구는 "변경 가능 구간"이다.

### 07 · 실행 안내 (`ActionPlan.tsx`)

머리글은 판정에 맞춘다. `keep`이면 `"확인된 조건에서는 유지가 유리합니다"` + 그래도 바꿀 때의 순서.

단계는 CLAUDE.md 순서 그대로다(빠진 입력·중도해지가 없으면 그 단계는 생략된다).

1. (있으면) 빠진 입력 확인 — `trigger.missing`
2. 새 상품의 **발급 가능 여부와 우대 인정 조건 확인** ← "먼저 만듭니다"가 아니다
3. **자동납부·결제계좌를 옮기고 인정 시점 확인** ← "실적을 옮깁니다"가 아니다
4. 이번 달 판정 종료까지 대기
5. **중도해지·비가역 손실 경고** ← 해지 단계보다 **앞에** 온다
6. 기존 상품 정리 신청 — `"10월 1일부터 · 이번 달 판정 종료 후"`

- 비가역 손실 단계는 번호 원을 `--down`으로 칠하고 본문을 `--danger-bg` 면에 넣는다.
  순서상 그냥 지나칠 수 없게 만드는 것이 목적이다.
- `ContactSheet` 맨 아래: `"전화번호는 데이터에 없습니다 · 공식 앱·홈페이지에서 확인 ·
  시연용 샘플 창구 정보"`. 부서·시간도 샘플이라고 적는다.
- 기준 안 줄에 `다른 안 고르기` → 결과 상세로. **앱이 고른 `best`로 절차를 짜지 않는다.**

## 5. 시안에 없는 화면

`Connections` · `Evidence` · `Assets` · `Benefits` · `More`는 그리지 않았다.
토큰 교체(1단계)만으로 대부분 따라온다. 추가로 맞출 것:

- **`Connections`** — 노드 색을 네이비 계열로, 선은 `--line`, 선택된 선만 `--brand`.
  원 안 텍스트는 Pretendard 600. 선 개수는 `graph.edges`를 순회해 그린다(SVG 하드코딩 금지).
- **`Evidence`** — 약관 원문 블록은 결과 상세와 **같은 컴포넌트**를 쓴다(mono + `--highlight`).
  값 수정 입력은 `<label>` + `<input>`을 실제로 쓴다.
- **`Benefits`** — 홈에서 뺀 혜택 합계가 여기 `summarycard`로 온다.
  `연 850,000원`을 이 화면의 주인공으로 둔다.
- **`Assets`** — 상품 행은 결과 상세의 행 컴포넌트와 같은 모양(아이콘 타일 + 2줄 + 금액).

## 6. 플로우 변경 — 마지막에, 따로

`store.ts`의 `{ tab, stack }`은 그대로 쓸 수 있다. 바뀌는 건 두 가지다.

1. **`hub`가 시트로 렌더된다.** 라우트는 그대로, `AppShell` 대신 시트 컨테이너.
   홈에서 `push({ name: 'hub' })` 할 때 뒤 화면이 비쳐야 하므로, 홈을 언마운트하지 않는
   렌더 경로가 필요하다. `App.tsx`의 `key={route.name}` 재마운트가 걸림돌이다.
2. **`verdict`에서 `timeline`으로 직접 간다.** 지금은 `impact`를 거쳐야 한다.
   `timeline`은 이미 독립 라우트라 `push` 한 줄이면 된다.

`analyzing → verdict → impact → actionplan` 순서 자체는 **바꾸지 않는다.**
CLAUDE.md의 "결론 먼저"가 이미 그 순서다.

## 9. 적용하면서 시안과 다르게 둔 것

CLAUDE.md가 이기거나, 실제 데이터에서 시안이 깨진 경우다.

- **폰트** — `pretendard` 패키지의 dynamic-subset CSS를 쓴다(전체 파일은 2MB). IBM Plex Mono는
  `@fontsource/ibm-plex-mono`의 latin 400만 넣는다.
- **mono는 숫자·날짜에만** — 약관 원문·샘플 칩·"n / 4 단계"처럼 한글이 섞인 줄을 mono로 쓰면 고정폭 공백 때문에
  글자 사이가 벌어진다. 약관 원문은 Pretendard로 쓰고, 원문 느낌은 인용 면과 추출 구간 형광으로 낸다.
- **비교 결과의 손실/절감 막대** — 시안은 금액 범례를 적지만, CLAUDE.md가 절감액을 결과 상세에만 두므로
  비율 막대와 이름("잃는 혜택 / 줄어드는 비용")만 그린다.
- **차트 x축** — "3개월 유지" 같은 라벨이 막대 폭을 넘어 "3개월"로 줄인다. 전체 문구는 `aria-label`에 있다.
- **관계도 선** — `--line`은 흰 면에서 보이지 않아 `--sep`(#c9c6c0)을 쓴다. 고른 선만 `--brand`.
- **토큰 추가** — `--up-bg` `--down-bg`(기존 화면이 쓰던 연한 손익 면), `--fs-hero`(38px),
  `--line-3` `--track` `--surface-sel` `--sep`(시안에서 되풀이되던 리터럴 색).
- **허브** — 첫 행 강조를 두지 않는다. 한 행만 강조하면 앱이 그 항목을 권하는 것처럼 읽힌다. 시트 뒤 화면은 `inert`로 포커스를 막는다.
- **54px 윗여백** — 데스크톱 폰 프레임에서만. 모바일 브라우저에서는 `env(safe-area-inset-top)`만 둔다.
- **차트 값** — 양 끝 값만 적되, 가운데 막대는 누르면 그 구간 값이 보인다(모바일엔 hover가 없다).
- **보류 결과** — 호박색 면과 "전체 비교 보류" 배지로 유지·변경 결과와 한눈에 가른다.
- **영향 카드 연결선** — 카드 사이를 아이콘 중심에서 짧은 선으로 잇는다(연결 개념을 시각으로 유지).
- **아이콘 색** — 면은 중립, 아이콘 색만 상품 종류별 저채도 색(`.k-*`). 손익·출처 태그 색과 겹치지 않게.
- **출처 태그** — 10px은 발표 화면에서 읽히지 않아 11px.
